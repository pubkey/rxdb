TanStack DB with Capacitor & Ionic: Offline Storage Guide

TanStack DB gives your Capacitor or Ionic app live queries and optimistic mutations, but it is an in-memory reactive store: persistence and sync come from the collection implementation you choose. RxDB is a local-first NoSQL database that runs inside the Capacitor webview and stores data in SQLite on the device filesystem, and the official @tanstack/rxdb-db-collection package puts it underneath TanStack DB as described in TanStack DB + RxDB. This page explains which storages are safe in a hybrid app, walks through a complete Capacitor setup with the SQLite storage, and shows where backend sync fits in.

Where a Capacitor App Can Store Data​

Capacitor apps run your web code in a native webview. This makes them more web-like than React Native: Web APIs like IndexedDB and localStorage are available, so most browser RxStorage plugins work out of the box. But there is a catch. The operating system treats webview storage as disposable and can clean it up when the device runs low on space or the app has not been used for a while. You cannot rely on that data surviving forever.

For production hybrid apps the recommended option is the SQLite RxStorage. It writes to the device filesystem instead of the webview, so the data is persistent and will not be cleaned up by any process. SQLite is also much faster than IndexedDB because it does not have to go through the browser's permission layers, and Android and iOS already ship with a built-in SQLite engine. For the native binding, RxDB uses the @capacitor-community/sqlite package through the getSQLiteBasicsCapacitor adapter.

Two versions of the SQLite storage exist:

  • Trial version: ships free with RxDB core as getRxStorageSQLiteTrial. It passes the full storage test suite but uses no indexes, is limited to 500 non-deleted documents, and runs queries in memory. Use it for evaluation and prototypes only.
  • RxDB Premium 👑 version: the production-ready getRxStorageSQLite with full query support and performance optimizations.

While testing and prototyping you can also use the free localStorage-based storage inside the webview and switch to SQLite later. Switching storages is a configuration change, not a rewrite. Your TanStack DB code does not change at all.

Adding Backend Sync​

Mobile devices go offline all the time: in the subway, in elevators, on airplane mode. Because RxDB owns the storage layer, your app also gets RxDB's Sync Engine for free. Replication is configured on the RxCollection only, TanStack DB never talks to the backend. Documents pulled from the server land in SQLite and stream into your TanStack DB collections automatically, and local writes are pushed back with retries and checkpoints, so the app resumes exactly where it left off when connectivity returns. The general pattern is described in How to Sync TanStack DB with Your Backend, and the full offline behavior including conflict handling is covered in Building an Offline-First App with TanStack DB and RxDB.

When TanStack DB Alone Is Enough​

TanStack DB has its own persistence answer for Capacitor: the @tanstack/capacitor-db-sqlite-persistence adapter persists collections to SQLite, and @tanstack/offline-transactions queues mutations while offline. When your app only needs to survive a restart and you sync through Electric or PowerSync anyway, that setup is a good fit and you do not need RxDB.

The RxDB collection is the better choice when you want a full database under your store: one storage abstraction that also covers the browser and Electron, replication with any backend, encryption of local data, schema migrations, and conflict resolution. Encryption in particular matters on mobile, where a stolen device means direct access to the SQLite file. RxDB is also a proven Ionic storage layer on its own, so you keep direct access to the RxCollection for indexed queries against large datasets.

FAQ​

Does TanStack DB work with Capacitor and Ionic?

Yes. TanStack DB is plain JavaScript and runs in the Capacitor webview with React, Angular, Vue, Solid, or Svelte bindings. It keeps data in memory, so pair it with a persistent collection implementation like the RxDB collection to make the data survive app restarts.

Can I use IndexedDB or localStorage for TanStack DB in a Capacitor app?

Yes, but only for prototyping. Webview storages work inside Capacitor, and the OS can delete them when the device runs low on space. For production, use the SQLite RxStorage which writes to the device filesystem and is not subject to webview cleanup.

Is the RxDB SQLite storage for Capacitor free?

No, not the full version. The production SQLite storage is part of the RxDB Premium 👑 plugins. A free trial version (getRxStorageSQLiteTrial) ships with RxDB core and is limited to 500 documents without indexes, and the free localStorage-based storage works for testing inside the webview.

Does the RxDB collection for TanStack DB work with Ionic Angular or Vue?

Yes. The rxdbCollectionOptions() function targets the framework-independent createCollection() API, so it works with @tanstack/angular-db, @tanstack/vue-db, and the other official bindings. RxDB itself is framework-agnostic as well.

Does the same code run as a PWA in the browser?

Yes. Swap the SQLite storage for the IndexedDB RxStorage or another browser storage and the rest of the code stays identical. See Building an Offline PWA with TanStack DB and RxDB for the browser setup.
