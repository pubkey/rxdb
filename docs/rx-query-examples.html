RxQuery Examples

RxDB queries are written in the Mango query syntax, a JSON-based query language that works like MongoDB queries. You pass a Mango query to find(), findOne() or count() of an RxCollection and get back an RxQuery. Because a Mango query is a plain JSON object, it can be typed with TypeScript, composed by code, and optimized by the EventReduce algorithm. If you prefer chained methods like .where('priority').gt(5), use the query builder, which creates the same Mango queries.

All examples on this page use the todos collection and the example documents from the example schema.

The Query Object​

A Mango query is an object with these fields:

FieldDescription
selectorThe conditions a document must match. An empty selector {} matches all documents.
sortAn array of { field: 'asc' | 'desc' } objects.
skipThe number of documents to skip.
limitThe maximum number of documents to return.
indexForces the query to use a specific index. See setting a specific index.

Fields inside nested objects are selected with the dot notation. The field path has to be quoted:

Notice that a document without the nested object also matches negated conditions like $ne. The query { 'assignee.name': { $ne: 'Alice' } } returns todo2, todo3 and todo4, because todo3 and todo4 have no assignee at all. Add { assignee: { $exists: true } } when you only want documents that have the field.

$gtis greater than the value{ priority: { $gt: 5 } }todo1, todo3

Regex Queries​

$regex matches string fields against a regular expression. Flags like i for case insensitive matching go into $options. The regex has to be a string. A RegExp instance is not allowed, because it cannot be serialized with JSON.stringify() and it is mutable, which would cause undefined behavior when the RegExp is changed after the query was created.

Keep in mind that regex queries cannot use an index in most cases, so they have to scan all documents. For large collections it is faster to store a lowercase copy of the field and query it with $eq, as shown in the RxQuery FAQ.

Sorting​

sort is an array of objects, each with one field and the direction 'asc' or 'desc'. The documents are sorted by the first entry, and the later entries decide the order when the earlier fields are equal:

To sort by an element of an array, write the array index with the dot notation. Documents where the element does not exist are sorted first in ascending order:

The bracket notation like { 'tags[0]': 'asc' } is not supported, because RxDB resolves nested fields only by the dot notation. In dev-mode such a sort throws QU20.

RxDB always appends the primary key as last sort field, so the result order is deterministic and never depends on the insert order. When a query has no sort, RxDB picks a sort order that fits the best index. Set sort explicitly when your code depends on the order. Sorting is fastest when the sort fields are part of an index.

Query Rules​

RxDB validates queries in dev-mode to catch mistakes early:

  • Fields must be in the schema: Top level fields in the selector and in sort must be defined in the schema. Otherwise the query throws QU13.
  • No undefined values: A query must not contain fields with the value undefined, because JSON serialization would drop them silently and change the meaning of the query. This throws QU19.
  • No RegExp instances: Use a $regex string instead. This throws QU16.
  • Only the known query fields: The query object may only contain selector, sort, skip, limit and index. This throws QU11.

RxDB supports the operators $eq, $ne, $gt, $gte, $lt, $lte, $in, $nin, $exists, $type, $regex (with $options), $size, $mod, $elemMatch, $and, $or, $nor and $not. Queries always return full documents. There are no projections or aggregations, because the documents are already in the same JavaScript process as your application code. Read more in the RxQuery FAQ.

Adding Query Operators​

RxDB runs queries with the mingo library. Mingo implements most MongoDB query operators, but RxDB only loads the operators listed above, because every loaded operator adds to the bundle size of your app. A query with any other operator fails with unknown query operator. There is no option to load more operators at runtime. To add one, change the RxDB source code and open a pull request:

  1. Load the operator in src/rx-query-mingo.ts. Import it from mingo/operators/query and add it to the query object of Context.init():
  1. Add the typing to MangoQueryOperators in src/types/rx-query.d.ts, so that TypeScript accepts the operator in a selector.
  2. Add a test with testCorrectQueries() in test/unit/rx-storage-query-correctness.test.ts. These tests run against every RxStorage, so they also catch storages that do not use mingo for the given query.
  3. Check the bundle size with npm run build and npm run test:bundle-size. If the size increase is intended, run npm run bundle-size:update and commit the updated limits.

The contribution guide explains how to set up the repository and run the tests.
