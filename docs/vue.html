Using RxDB with Vue

RxDB integrates into Vue through the reactivity-vue plugin. The plugin converts the observables of each RxQuery and each RxDocument into Vue refs, so that you can use them in a template like any other reactive state.

This page shows how to create the RxDatabase, provide it to your components with a Vue plugin, and read and write data with the Composition API. The same code runs in the browser, in Electron, and in Capacitor apps. Only the storage differs between these platforms.

General Concept​

RxDB is internally reactive and emits changes via RxJS observables. Vue tracks changes through refs. The reactivity-vue plugin bridges these two models: reactive values that are accessed with a double dollar sign like query.$$ or document.name$$ return a Vue shallowRef instead of an observable.

The ref subscribes to the observable when it is created and unsubscribes when the current effect scope is disposed. This means you have to access $$ inside of setup() or <script setup>, where Vue ties the subscription to the lifetime of the component.

Create the Database​

Create the database outside of your components and set VueRxReactivityFactory as the reactivity option. The returned Vue plugin provides the database to all components, and useDatabase() injects it.

3

Provide the Database to the App​

Wait for the database before you mount the app. This way each component can use the database without a loading check.

4

Render a Query​

Access the $$ property of a query to get a ref with the query results. The ref updates each time a matching document is inserted, updated, or deleted. The value is undefined until the query has emitted its first result.

No manual subscription or cleanup code is required. The subscription ends when the component is unmounted.

5

Write Data​

Writes are done with the normal RxCollection and RxDocument methods. Each query that is affected by the write emits a new result, so the templates update without any additional code.

Using Observables Without the Plugin​

The reactivity plugin is optional. Each reactive value also has a single dollar sign variant like query.$ that returns an RxJS Observable. You can subscribe to it and write the results into your own ref. In this case you have to unsubscribe when the component is unmounted.

The same pattern works for the observables of an RxReplicationState like active$ and error$ when you want to show a sync indicator.

FAQ​

Does RxDB work with Vue 3 and the Composition API?

Yes. The reactivity-vue plugin of RxDB returns Vue refs for queries, documents, and document fields. You access them with the double dollar sign inside of <script setup>, for example collection.find().$$, and use them in the template like any other ref.

Do I have to unsubscribe from RxDB queries in Vue components?

No, not when you use the $$ refs of the reactivity plugin. The plugin registers the cleanup with onScopeDispose(), so the subscription ends when the component is unmounted. You only have to unsubscribe yourself when you call .subscribe() on an observable.

Can I use RxDB together with Pinia?

Yes. Pinia and RxDB solve different problems. Keep persistent data in RxDB collections and query it with refs, and use Pinia for temporary UI state like the selected tab or an open dialog. Do not copy query results into a Pinia store, because the RxDB refs are already reactive.

Which RxDB storage should I use in Vue?

For a quick start in the browser use the localStorage RxStorage. For bigger datasets use the IndexedDB RxStorage or the OPFS RxStorage. In Capacitor and Electron apps the SQLite RxStorage is the recommended choice.
