Using RxDB with Angular

RxDB works in Angular out of the box because both are built on RxJS. Each RxQuery and each RxDocument exposes an observable that you can render with the async pipe. With the reactivity-angular plugin, the same values are also available as Angular Signals.

This page shows how to create the RxDatabase in an Angular service and how to read and write data in components. The same code runs in the browser, in Ionic, and in Capacitor apps. Only the storage differs between these platforms.

General Concept​

The database is created once, before the app renders, and is then handed to the components through a service. Components never create or configure the database. They only consume it.

There are two ways to bind RxDB data to a template:

  • Signals: The reactivity-angular plugin converts each observable into a Signal. Reactive values are accessed with a double dollar sign like query.$$ or document.name$$.
  • Observables: Each reactive value has a single dollar sign variant like query.$ which returns an RxJS Observable for the async pipe.

Both ways can be used at the same time in the same component.

Usage​

1

Installation​

Install RxDB and RxJS into your Angular project:

2

Create the Database Service​

Create the database in an init function and expose it through an injectable service. The reactivity factory needs the Angular Injector, so inject(Injector) has to be called before the first await while the injection context is still active.

3

Initialize the Database on App Start​

Run initDatabase() in an app initializer. Angular waits for the returned promise before it renders the first component, so each component can use the database without a loading check.

4

Render a Query with Signals​

Access the $$ property of a query to get a Signal with the query results. The signal updates each time a matching document is inserted, updated, or deleted. The value is undefined until the query has emitted its first result.

The signals are bound to the injector that was passed to createReactivityFactory(). This is why they also work with ChangeDetectionStrategy.OnPush and in zoneless applications.

5

Render a Query with Observables​

Instead of signals you can use the observable of the query together with the async pipe. The pipe subscribes when the component is created and unsubscribes when it is destroyed.

6

Write Data​

Writes are done with the normal RxCollection and RxDocument methods. Each query that is affected by the write emits a new result, so the templates update without any additional code.

Signals for Single Documents and Fields​

Signals are not limited to queries. An RxDocument exposes a signal for the whole document, for each field, and for its deleted state. This is useful for detail views and edit forms.

A findOne() query also has a $$ property. Its signal contains the document or null when no document matches. All available reactive getters are listed in the custom reactivity documentation.

Replication Status​

An RxReplicationState exposes observables like active$ and error$. Convert them with toSignal() from @angular/core/rxjs-interop to show a sync indicator.

Server-Side Rendering​

RxDB also runs during Angular server-side rendering. On the server there is no IndexedDB or localStorage, so you have to use the memory storage there and skip the replication. The RxDB Angular example switches the storage through the Angular environment files.

FAQ​

Does RxDB work with Angular Signals?

Yes. The reactivity-angular plugin of RxDB converts each observable value into an Angular Signal. You get the signal with the double dollar sign, for example collection.find().$$ or document.name$$. The plugin uses toSignal() from @angular/core/rxjs-interop under the hood.

Do I need NgZone or zone.js to use RxDB in Angular?

No. Signals from the reactivity plugin notify Angular directly and the async pipe marks the component for check on each emit. Both work in zoneless applications and with ChangeDetectionStrategy.OnPush.

Where should I create the RxDB database in an Angular app?

Create it once in an app initializer with provideAppInitializer() and expose it through an injectable service. Do not create the RxDatabase inside of a component, because components are created and destroyed many times while the database must exist only once.

Which RxDB storage should I use in Angular?

For a quick start in the browser use the localStorage RxStorage. For bigger datasets use the IndexedDB RxStorage or the OPFS RxStorage. In Ionic and Capacitor apps the SQLite RxStorage is the recommended choice.
