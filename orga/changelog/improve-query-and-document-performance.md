- IMPROVE performance of `findByIds()`: the query cache key is no longer built from a sorted copy of all ids. With `3000` ids, `find-by-ids` in the memory performance test went from 4.80ms to 3.26ms. Queries with the same ids in a different order now get their own cache entry, so each result `Map` keeps the order of its own ids.
- IMPROVE performance of the `DocumentCache`: RxDocuments are cached by their revision, and the `_meta.lwt` is compared on lookup instead of being converted to a string for the cache key. `find-by-query` went from 3.32ms to 2.60ms.
- IMPROVE performance of nested property access on RxDocuments: the nested value is no longer looked up again from the document root on each access. `property-access` went from 6.57ms to 4.02ms.
- IMPROVE query planner: string and number fields that are matched with `$eq` are ignored when checking whether the index order matches the sort order, as was already done for boolean and enum fields. The storage no longer has to re-sort these query results. `find-by-query-parallel-4` went from 3.63ms to 2.87ms.
- IMPROVE performance of database and collection creation: schema hashes are cached, so the same schema is not hashed again for each collection or database. `time-to-first-insert` went from 1.40ms to 1.22ms.
