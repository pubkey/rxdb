- FIX Firestore replication: the pull and push handlers ran their reads inside of a `runTransaction()` that never used the transaction, so the reads went through the local cache. While offline, a pull resolved with no documents instead of failing, a push hung, and the push conflict check could compare against stale cached data. When Firebase Auth failed to refresh the token with `auth/network-request-failed` during the commit of that empty transaction, the Firestore client failed with `INTERNAL ASSERTION FAILED: Unexpected state` and the replication stopped until the page was reloaded. The handlers now read with `getDocsFromServer()` and `getDocFromServer()` without a transaction, so offline pulls and pushes emit an `unavailable` error on `error$` and retry until the network is back.
