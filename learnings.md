# Learnings

Notes about things that went wrong and had to be fixed, reverted, or reworked.

## examples/todo-http-sse

- **Hooks race with manual builds**: The first `npm run build` failed with `ENOTEMPTY: directory not empty, rmdir dist/...` because a hook ran a build at the same time. The `PostToolUse` hook in `.claude/settings.json` runs an async `npm run build` after every write to a file matching `*src/*.ts`. That pattern also matches `examples/*/src/*.ts`, so every edit in the example's `src/` folder started a full repo build in the background. Retrying the build fixed it. Do not start a manual build right after editing a `src/*.ts` file, or retry when it fails with `ENOTEMPTY`.
- **Lint covers new example folders**: The root `eslint .` lints every folder under `examples/` that is not in the ignore list of `eslint.config.mjs`. The first version of the example used non-null assertions (`querySelector(...)!`), a type literal without a trailing semicolon, and a value that was only used as a type. All three are lint errors in this repo. Write example code with the repo lint rules in mind.
- **`count()` needs an index-satisfied selector**: A test ran `count({ selector: { id: { $regex: '^bulk-' } } })` and dev-mode threw `QU14`. `$regex` on the primary key is fine in a `find()` query. The problem was `count()`: a count query must use a selector that the index fully satisfies (or the database must set `allowSlowCount: true`), and a `$regex` selector cannot be satisfied by an index. A range like `{ $gte: 'bulk-', $lt: 'bulk.' }` works with `count()`.
- **Read the error before writing it down**: The first version of the entry above said that `$regex` on the primary key is not allowed. That was a guess from a truncated test output, not from the error code. Look up the error code (here `QU14` in `src/plugins/dev-mode/check-query.ts`) before drawing a conclusion.
- **Hand-written EventSource type**: The first version of `replication.ts` declared its own `EventSourceLike` type. `tsc` rejected passing the browser `EventSource` because the DOM `onmessage` signature takes a full `MessageEvent`. Use `typeof EventSource` from the DOM lib instead of re-declaring browser types, and run `tsc` on the example before relying on the tests (tsx strips types and does not type-check).
- **Conflict handler returned a changed master state for deletions**: The first version of `todoConflictHandler.resolve()` returned the deleted server document with a new `updatedAt` when the server state was deleted. The resolved state then differed from the server state and was pushed again for no reason. It now returns `realMasterState` unchanged when the server deleted the document, and only bumps `updatedAt` when the local side deleted it.
- **Comment above the wrong option**: In `replication.ts` a comment about opening the `EventSource` on start was placed above `autoStart: true`, which is the default and has nothing to do with the `EventSource`. The option and the comment were moved to the `startPromise` code that opens the connection.
- **`pkill` in a chained command killed the shell**: A command ran `pkill -f "server/index.ts"` followed by a `sed` edit of `index.html`. The shell exited with code 144 and the `sed` never ran. The most likely cause is that the `pkill -f` pattern also matched the command line of the shell itself (this was not verified). Run `pkill` as its own command and check that later edits were applied.
- **Missing favicon caused a console error**: The browser smoke test reported a 404 for `/favicon.ico`. `index.html` now sets `<link rel="icon" href="data:," />`. Run the app in a real browser and read the console before calling a UI done.
